# AGENTS.md

This repository or directory started as an exported Productive K3S stack
bootstrap bundle. It can be used as-is to replay the exported installation, or
as the initial codebase for a project-specific Kubernetes bootstrap repository.

## Project Origin

- Generated by: `productive-k3s-core stack export`
- Subject: `{{subject_ref}}`
- Packaged artifact: `{{artifact_name}}`
- Runtime entrypoint: `./productive-k3s-core.sh`

The bundle vendors the Productive K3S Core runtime files needed to replay the
stack installation. It should not need to download a separate Core bundle before
starting.

This code is intentionally ordinary shell and packaged YAML/TGZ content. A
downstream project may adapt it, wrap it, replace the packaged stack, or fork the
vendored runtime. Prefer preserving the notes below so future maintainers and
agents can still identify what came from Productive K3S and what became local
project code.

## Code Map

- `install.sh`: top-level installation entrypoint for this exported bundle.
  It loads `install-config.env`, runs `preflight.sh` by default, and then
  delegates to the bundled Core runtime.
- `preflight.sh`: validates the local bundle shape, packaged stack metadata,
  and host prerequisites before installation.
- `install-config.env`: generated configuration defaults captured when the
  bundle was exported. This is the preferred file for environment-level changes.
- `manifest.json`: generated metadata describing the exported subject and
  command. Treat it as audit data.
- `{{artifact_name}}`: packaged stack artifact consumed by Core. It contains
  `stack.yaml` and bundled add-on packages when the stack uses bundled
  resolution.
- `productive-k3s-core.sh`: public Core runtime entrypoint vendored into this
  bootstrap.
- `scripts/`: vendored Core runtime internals. The most relevant paths are
  `scripts/productive-k3s-core.sh` for command dispatch,
  `scripts/addons-runtime.sh` for add-on package handling, and
  `scripts/apply.sh` for the stack installation execution path.

## How To Operate

- Run `./preflight.sh` before installation to verify the bundle structure,
  stack package metadata, and host prerequisites for stack mode.
- Run `./install.sh` to execute the stack installation.
- Use `./install.sh --skip-preflight` only after preflight was already run in
  the same target environment.
- Use `./install.sh --preflight-only` when an automation agent should validate
  the bundle without installing.

## Editing Guidance

- Treat files under `scripts/` and `productive-k3s-core.sh` as vendored
  Productive K3S runtime code until the project intentionally forks them.
- Prefer changing `install-config.env` or passing runtime flags to
  `install.sh` over editing vendored runtime scripts.
- If this bootstrap becomes the starting point for a forked deployment project,
  keep local project logic outside the vendored runtime where possible. Add
  wrapper scripts, environment files, documentation, or CI around `install.sh`
  instead of patching Core internals.
- If the packaged stack itself must change, rebuild or replace
  `{{artifact_name}}` from the source stack/add-on repositories and keep the
  updated artifact next to this file.
- Keep `manifest.json`, `{{artifact_name}}`, `README.md`, and this file
  together if this bootstrap bundle is copied into another repository.
- Do not assume this bundle contains cluster credentials. Installation still
  needs access to the target Kubernetes cluster through the environment used by
  Core, such as `KUBECONFIG` or the host's managed cluster runtime.

## Suggested Agent Workflow

1. Read `README.md`, this file, `manifest.json`, and `install-config.env`
   before editing.
2. Inspect `{{artifact_name}}` with `tar -tzf {{artifact_name}}` to understand
   the packaged stack and bundled add-ons.
3. Run `./preflight.sh` after any change to configuration or packaged
   artifacts.
4. Add local automation around `install.sh` for project-specific behavior.
5. If changing vendored runtime files, treat that as a fork of Productive K3S
   Core and document the divergence in this repository.

## Implementation Scope

This bootstrap installs an already-packaged stack. It does not own catalog
lookup, add-on source curation, or profile/infrastructure provisioning. Those
responsibilities live above or beside Core in the Productive K3S ecosystem. A
future agent should preserve that boundary unless the project intentionally
forks the vendored runtime.
